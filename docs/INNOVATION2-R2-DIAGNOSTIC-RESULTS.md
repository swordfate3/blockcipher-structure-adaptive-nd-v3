# 两轮剩余错误诊断：已见组合仍出错，两个初始化均未达99%

## 结论

用户要求“推进”，本批按[运行前计划](INNOVATION2-R2-DIAGNOSTIC-PLAN.md)保持原332参数模型、
数据量、优化器及每项800更新，使用同一新面板做init17/18各真实/null，全部正常完成。
批次`innovation2-r2-diagnostic-20261024-023910`已关闭，没有追加训练或升轮。

- 两个初始化真实TEST分别 **96.6675%和92.7368%**，均未达到99%及BCE<0.05目标。
- 两者所有DEV错误都在**完整模型输入签名已被TRAIN覆盖**的行上；TRAIN本身也有错误且没有同签名标签冲突。
  因此“仅仅没见过这些输入组合”不能单独解释当前误差；在本预算下已见数据仍未完全拟合。
- init17的TRAIN/DEV错误全部集中在公开`U[j+1]=0,U[j+8]=0`两格；init18在这两格也出错，并在其他格有额外错误。
  这是聚合分布，**没有保存逐条错误，不能据相同格错误数声称两次错的是完全相同行**。
- 新面板上的同预算结果对初始化有差异；只是两个init的观察，不是随机初始化总体分布或某种优化理论的证明。
- 三个局部隐藏输出都不是常数，但动态范围不等于正确实现布尔局部函数，未验证其为真实密码状态。

## 诊断一：完整模型输入签名覆盖

bit0模型只依赖公开输入位置`[0,2,3,4,9,10,16,33,34,40]`，10bit最多1024种签名。
TRAIN4096条覆盖1006种签名，真实标签同签名无冲突。
DEV1024条中，1010条的签名在TRAIN中出现过，14条未出现。
“签名重复”不是完整64bit明文重复；明文全局唯一，有限局部函数的输入投影可以重复。

| init | TRAIN错误 | DEV seen行数/错误 | DEV unseen行数/错误 |
|---|---:|---:|---:|
| 17 | 122 / 4096 | 1010 / **42** | 14 / **0** |
| 18 | 290 / 4096 | 1010 / **75** | 14 / **0** |

因此未覆盖签名不是本批DEV错误的直接位置。未见组只有14条，0错也不证明对未见组合总体泛化完美，
更不证明数据量永远无关。当前证据指向已见组合的拟合/表示学习或优化缺口，尚未区分具体机制。

## 诊断二：公开U三bit的错误分布

`U=Y0 XOR F(X0)`是纯公开明文函数，不是真实第一轮状态。
三位顺序为`U[j+1],U[j+8],U[j+2]`，实际bit0为`U[1],U[8],U[2]`。
组内检查的残差标签是最终标签XOR公开X[j]；两个真实臂全部非空格内一致。
这些特征只用于报告，不输入模型或作为中间监督。

init17错误局限在U前两位00，init18该区域错误数相同并增加其他区域。
