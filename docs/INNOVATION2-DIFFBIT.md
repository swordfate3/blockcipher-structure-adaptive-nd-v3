# 差分输出位预测：v1 实现与首次跨 key 结果

## 为什么换成这个任务

绝对位任务 `y = f(P, K)` 里 K 未知，任何模型的天花板就是边缘概率——这解释了 r5 的 50%，
也解释了为什么梯度方法在 r4 上毫无样本效率优势。差分位

```text
y = bit_j( E_K(P) xor E_K(P xor ΔP) )
```

在第 1 轮里密钥被直接异或抵消，第 2 轮起只以**统计偏置**形式残留，所以：

- 信号是"偏置"，不是"确定函数"；
- 只有**跨 key 训练 + 留出 key 评估**才有意义。

本轮先把任务做成可复现的工程能力，并跑出第一个数据点。

## 实现

新增 `data/diffbit.py`、配置字段与训练接线（`model_kind=mlp`，`dataset=simon-diff`）：

| 字段 | 含义 |
|---|---|
| `input_difference` | 公开固定差分 ΔP（非零 64 位） |
| `key_count` | 密钥池大小 |
| `train_key_count` | TRAIN 使用的 key 数；**DEV/TEST 只用剩余未见 key** |

- 每个 key 由 `key_seed` 与索引经 SHA-256 派生，密钥只存在于数据生成路径。
- 三种 split 的明文互不重叠；标签 `= bit_j(C(P) xor C(P^Δ))`。
- `label_mode=null` 提供同 split 的随机标签对照。
- `train_pool`/`shuffle_seed` 等既有字段对差分同样生效（不影响历史 SHA，缺省不写入）。

`round_one_reference`：**无密钥精确差分**。一轮 SIMON 为
`(L,R) -> (R ^ f(L) ^ k, L)`，做差后 `ΔL' = ΔR ^ (f(L) ^ f(L^ΔL))`，`ΔR' = ΔL`，与 k 无关。
测试用 3 个随机 key × 4 个目标位验证它与真实加密逐位一致——这是纯数学恒等式，不是训练结果。

## 必须记住的陷阱：多数目标位是"退化"的

对 14 个 Δ × 轮数 2/3/4 × 全部 64 位共 **2688 个组合**做偏置筛选（192 行样本、4 个 key）：

| 类别 | 数量 | 含义 |
|---|---:|---|
| 非退化（正例率 0.10–0.90） | **727** | 才值得训练 |
| 其余（恒 0 / 恒 1 / 近常数） | 1961 | **常数基线就 100%**，训练毫无意义 |

典型例子：Δ=0x1、r2、bit63 恒为 1；Δ=0x40、r2、bit0 恒为 0。
原因是稀疏 Δ 在低轮下只影响少数位，多数输出位根本没被触动。

**所以任何差分位结果都必须同时报"常数基线准确率"**，否则会把平凡命中当成模型能力。

## 首次跨 key 训练结果

选定候选：Δ=0x41、r3、bit22（筛选正例率 0.500、跨 key 极差 0.125）。
TRAIN 用 4 个 key、DEV/TEST 用另外 4 个**未见 key**；TRAIN4096 / DEV2048 / TEST2048，
batch256、20 epoch = 320 次更新、MLP 64 宽、Adam .01、CPU。

| 项目 | TEST 准确率 | 说明 |
|---|---:|---|
| 真实差分标签 | **54.35%** | 未见 key |
| 同面板随机标签 | 49.76% | 对照 |
| TEST 常数基线 | 50.44% | 只用 TRAIN 偏置 |

- DEV（也是未见 key）52.73%，与 TEST 同向；TRAIN 58.23% 明显更高，说明存在过拟合成分。
- 差值约 **+3.9pp vs 常数基线、+4.6pp vs null**。按 2048 样本二项标准误约 1.1pp，约 3.5σ——
  **但见下面的选择偏差警告。**

## 关掉这条线的那一步：key 边缘基线

之前只比"常数基线"（50.44%），那是个弱对手。真正该比的是**key 边缘基线**：
对每个测试明文，用 TRAIN 那批 key 分别加密取多数——这是任何不了解密钥的模型
**理论上能达到的最好结果**。实现为 `key_marginal_probability`，每次差分实验自动多报两列
（`key_marginal_baseline`、`accuracy_gain_vs_key_marginal`）。

| 面板 | TEST 准确率 | 常数基线 | **key边缘基线** | **相对边缘基线** |
|---|---:|---:|---:|---:|
| 原面板（data192401/key5） | 54.35% | 50.44% | **55.13%** | **−0.78pp** |
| 原面板 随机标签 | 49.76% | 50.68% | — | — |
| **新面板（data192402/key7）** | **47.41%** | 50.59% | 50.73% | **−3.32pp** |
| 新面板 随机标签 | 49.85% | 50.68% | — | — |

结论：

1. **没有任何"学到结构"的证据。** 原面板上模型 54.35% 看似高于常数基线 3.9pp，
   但**低于 key 边缘基线 0.78pp**——它只是在逼近"差分偏置本身"，没有额外利用明文结构。
2. **54% 本身也不可复现。** 换新面板 + 新 key 池后掉到 47.41%（低于随机），
   说明原数字是"候选筛选 + 特定面板"的产物。
3. 对照组一直接近 50%，没有异常。

这是一次**有价值**的负结果：它证明了在这套"单固定 Δ、单输出位、2–4 轮、小样本"的设置里，
差分位预测不产生可学的额外信息——继续调网络或加大训练量都不会改变这一点。

## 若还要继续，需要什么

要让差分方向重新有希望，必须先获得**真正好的差分特征**，而不是从 2688 个组合里按偏置筛：

- 做差分特征搜索（或直接采用文献中已发表的 SIMON 高概率特征）；
- 轮数要进入文献量级（SIMON64/128 经典到 31/44 轮），意味着成对输入、残差网络、
  中性比特等一整套方法；
- 目标要从"单比特准确率"改成"真/随机区分 + 密钥恢复"，否则无法与文献对话。

也就是说：**这不是继续调参的问题，而是要不要进入真正的差分密码分析的问题。**

## 不能由这一次得出的结论

1. ~~候选是从 2688 个组合里筛出来再测的~~ → 已用新面板/新 key 池复核，**未复现**（见上一节）。
2. 单候选、单 seed、320 次更新、一个小 MLP，没有做架构或训练预算比较。
3. 这是**单比特差分**预测，不是 Gohr 那类"真/随机对区分 + 密钥恢复"，也没有用到中性比特等技巧；
   与文献的轮数不可比。
4. 54% 是"统计偏置可学"，不等于该差分特征在实际攻击中可用。

## 下一步（建议顺序）

1. **同候选、新面板/新 key 复核**：确认 54% 不是筛选运气（最便宜、最先做）。
2. 在 r2/r3/r4 上各选 2–3 个已筛候选，做小矩阵：真实 / null / 常数基线三列并报。
3. 有稳定信号后，再讨论架构（残差网络、成对输入）与更长轮数。
