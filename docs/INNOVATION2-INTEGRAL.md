# 积分（立方体）平衡性：可证明的精确引擎与 r2–r6 前沿

## 方法：为什么能"证明"而不是"统计"

对立方体 `S`（这些明文位取遍全部 2^|S| 个值，其余位固定），把输出位写成 ANF，立方体求和等于
**superpoly**：

```text
Σ_cube f = Σ_{含 S 全部变量的单项式 m} (m 的系数) × (m 在 S 外变量的乘积)
```

它在**所有**固定值与**所有**密钥下都为零 ⟺ `f` 的 ANF 里**没有任何单项式包含 S 的全部变量**。

所以只要追踪"每个单项式在 S 上的投影是否存在"：
XOR 取并、AND 取两两并、明文活跃位为自己的投影、非活跃位与密钥为常量投影（空集）。
该传播是**过近似**，因此：

- `未出现全集投影` → **证明**平衡（对所有 key、所有固定值成立）；
- `出现全集投影` → 只表示"此处未证"，不代表不平衡。

这是单侧可靠（sound one-sided）判定，代价是可能放弃一些本可证明的目标。
精确的奇偶相消需要完整 ANF（r4 起爆炸），因此刻意不做。
模块不接收任何密钥：轮密钥按常量处理，正确性由下面的穷举验证保证。

## 验证：引擎声称的平衡，用真实加密逐个穷举核对

| 检查 | 结果 |
|---|---|
| 单元测试（1–3 轮、9 组立方体，逐目标穷举） | 通过 |
| r5 cube8：64 个目标 × 3 key × 3 固定值 | **576 个立方体和，0 矛盾** |
| r5 cube12：同上 | 576 个，0 矛盾 |
| r6 cube8：57 个目标 × 3 × 3 | 513 个，0 矛盾 |
| r6 cube12：64 × 3 × 3 | 576 个，0 矛盾 |
| 反向检查（引擎"未证"的目标是否真不平衡） | r5 cube4：10 个未证里 9 个求和为奇；r4 cube4：3 个里 1 个 |

"未证"一侧大部分确实不平衡，说明引擎不是空转；剩下少数是过近似造成的遗漏。

## 前沿：需要多大立方体才能覆盖全部 64 个输出位

| 轮数 | cube4 | cube6 | cube8 | cube10 | cube12 |
|---|---:|---:|---:|---:|---:|
| r2 | 64/64 | 64/64 | 64/64 | 64/64 | 64/64 |
| r3 | 64/64 | 64/64 | 64/64 | 64/64 | 64/64 |
| r4 | 61/64 | 64/64 | 64/64 | 64/64 | 64/64 |
| r5 | 54/64 | 64/64 | 64/64 | 64/64 | 64/64 |
| r6 | 38/64 | 51/64 | 57/64 | 60/64 | **64/64** |

读法：**SIMON64/128 在 5 轮时，用 2^6 = 64 个选择明文就能让全部 64 个输出位平衡；
6 轮需要 2^12 = 4096 个。** 这是定理级断言（superpoly 恒零），并由上述穷举抽样交叉验证。

边界（必须如实说）：

- 立方体只取**高字连续位**，未搜索任意位组合；最优立方体可能更小；
- `simon_cone` 目前只支持 1–6 轮，7 轮以上未评估；
- 引擎是过近似，真实前沿可能**优于**上表（更多轮/更小立方体），不会更差；
- 与文献不可直接比较：SIMON 的积分攻击文献通常用 2^31–2^32 量级数据打 15 轮以上，
  我们这张表只说明"小数据 + 低轮"的可证明性，不构成对文献的改进。

## 代价墙

`|S| = 12` 时单次判定已需数秒（支撑集上界 4096，AND 为两两并）；
`|S| = 16` 的朴素实现是 O(2^32) 级运算，当前实现不可行。
若要继续往上走，需要换成真正的位级 division property（带奇偶的 Todo/Xiang 规则）或 SAT/CP 搜索。

## 下一步（按性价比）

1. **换位级 division property（精确相消）**：把"未证"变成"已证"，前沿会往上抬；实现量中等。
2. **搜索任意位组合的立方体**：现在只扫了连续位，随机/贪心搜索可能找到更小的区分器。
3. 扩 `simon_cone` 到 7–8 轮，看前沿是否继续按"每两轮 +4 位"增长。
4. 把结论接到密钥恢复：积分区分器 → 猜测部分密钥 → 检查平衡，这是完整攻击的路径，
   但工作量远大于区分器本身。
