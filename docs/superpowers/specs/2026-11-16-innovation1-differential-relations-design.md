## 0. 一页说明

**目的**：沿用创新1的 shared-M 主干，研究明文对能否帮助预测多个输出差分位之间的奇偶关系。

例如，选中四个输出位置，将这四个位置的差分位异或：偶数次翻转标0，奇数次翻转标1。模型预测这个关系成立的概率。本轮固定4条这样的关系，每对明文得到4个标签。

```text
                    标签生成侧：固定未知K
明文P ─┬─ P ─────────── E_K ── C ──┐
       └─ P XOR α ────── E_K ── C′ ─┴─ ΔC=C XOR C′ ── 4个掩码奇偶标签
          │
          └─ 明文对 ── shared-M预测变体 ── 4个概率 ── 与标签计算损失
```

- 首轮建议：SIMON64/128、6轮、输入差分 `0x40`，整个周期固定一个未知密钥。
- 网络：沿用创新1几何stem、路由、96通道残差卷积；每组4对分别输出4条关系概率。
- 数据：小TRAIN 262,144对，大TRAIN 1,048,576对；DEV 65,536对；TEST 262,144对。
- 最大5次拟合：两档学习率、小/大数据比较、第二初始化、标签置乱对照。
- 预算提议：单GPU，总科学运行上限8小时；次数、步数和时间同时限制。超时留下部分结果。
- 主比较：留出集上的四关系平均BCE是否优于TRAIN常量与浅层基线；同时报告每条关系准确率、基线提升与不确定性。
- 产物：必要数据、配置与日志、每次best模型、实际结果图表；一个启动脚本，直接SSH/SCP取回。

## 1. 任务定义与方案比较

### 1.1 选定的目标类型

设 `E_K^(r)` 为r轮加密，`α != 0`，`P′ = P XOR α`，`ΔC = E_K^(r)(P) XOR E_K^(r)(P′)`。

第j条关系的标签为：

\[
y_j(P)=\langle\beta_j,\Delta C\rangle_{GF(2)}
      =\operatorname{popcount}(\beta_j\mathbin{\&}\Delta C)\bmod 2.
\]

模型输出 `p_j ∈ (0,1)`。标签为0表示选中位置发生偶数次翻转，标签为1表示奇数次翻转。预测对象是多位之间的奇偶关系，每条关系用一个布尔值编码。

| 已比较方案 | 优点 | 本轮决策 |
|---|---|---|
| 多位差分奇偶关系 | 标签含义明确、输出紧凑、可逐条评价 | 主方向；采用4条固定关系 |
| 小范围截断差分模式 | 直接研究若干位的联合模式 | 备选；本轮不增加分类头或实验 |
| 完整64位差分 | 覆盖完整输出差分 | 本轮范围过大，暂留后续 |

推荐依据是任务解释和实验可控性，尚无这些掩码可学或优于其他目标的实测证据。

### 1.2 首轮固定关系面板（提议）

位号统一为**整个64位字LSB0**，bit0为最低位；高32位是bit32—63。输入 `α=0x40` 翻转低字bit6。

| 关系 | 选中的全字LSB0位号 | 64位掩码 |
|---|---|---|
| R1 | 0, 9, 18, 27 | `0x0000000008040201` |
| R2 | 4, 13, 22, 31 | `0x0000000080402010` |
| R3 | 32, 41, 50, 59 | `0x0804020100000000` |
| R4 | 36, 45, 54, 63 | `0x8040201000000000` |

选位理由：同样权重4、覆盖两个半字、非相邻位置、四个掩码支撑互不相交，因此掩码线性独立。这个规则是预先固定的几何面板，**没有根据密码标签挑位，也没有借用某条密码差分路径**。掩码独立不保证标签统计独立，也不保证各关系难度相同。

首轮所有掩码一起训练、一起报告，不按最佳TEST掩码给总结果。后续若要发现更强关系，应另立有界发现实验。

### 1.3 密钥协议

本轮建议整次实验固定一个私有随机128位K，所有划分、所有fit共用这个K。该协议研究固定key下的预测函数。随机密钥由标签生成侧产生，与公开采样种子分离；真实key、轮key、内部状态均不进入模型、checkpoint、日志或报告。只保存必要明文代表和关系标签，便于独立evaluate，避免保存key用于再生。

创新1原协议每组重抽key。本文的fixed-key是本次已确认方案中的明确实验变更。每组换key将研究密钥平均后的条件概率，可作后续独立任务；本周期不混用两种协议。

### 1.4 信息边界

模型可见明文对和创新1原有public13任务卡；四个输出头固定对应R1—R4。密文只用于生成标签。仅输入 `α` 时同任务样本输入相同，只能估计总体比例，因此必须提供具体明文。

给定完整密文对后，关系可以直接计算；本任务不会把密文对作为预测输入。公开掩码本身是合法任务参数。

## 2. 网络：创新1主干的预测变体

当前源码参考：`cipher-lab/src/cipher_lab/models/shared_m/{system,components,router}.py` 与 `representations/input.py`。

### 2.1 输入与逐对输出

- 输入 `[B,4,2,64]`：B组，每组4对明文；模型内部bit编码MSB0，数据层负责与上述LSB0目标坐标的明确转换。
- 每对产生原始两端及XOR三通道 `[B,4,3,64]`。
- 三种已有几何stem：local、word、nibble；各取9位置，输入27通道。
- 原public13路由选top2 stem并加权；路由只依赖任务卡，本轮所有样本同卡。
- 得到 `[4B,96,64]`，通过共享卷积残差主干。
- 每对展平为6144维，两个读出支路相加：`Linear(6144,4)` 与 `Linear(6144,64)→ReLU→Linear(64,4)`。
- 输出 `[B,4,4]`，分别对应每对的R1—R4；四对的标签可能相同也可能不同。损失/评价展平为 `[4B,4]`，不跨对平均logit。

四对只作为批组织；每对独立编码，GroupNorm按对计算，无组内信息交换。该实验继承shared-M主干，暂不检验四密码联合训练的共享收益。

### 2.2 沿用与调整

| 部分 | 选择 |
|---|---|
| stem_width/channels/norm_groups | 96/96/8 |
| suffix_kernels | `[3,5,7,9,11]`，每块两个Conv1D+GN+ReLU及残差 |
| head_hidden/router_hidden | 64/16 |
| 输入关系特征 | 跳过原密文关系通道、SKINNY backstep；只用原始对与XOR |
| 预测读出 | 从组级单logit改为逐对4logits |
| 权重来源 | 从头初始化；禁止载入旧训练权重 |
| 初始化细节 | 沿用原卷积/线性默认初始化、GN初值、三stem初始网络权重复制；预测头残差支路末层置零 |

原public13含算法类别、字长、旋转常数等，几何邻域也带有原有归纳偏置；本文如实保留这些创新1已有设计。新变体不添加密码轮函数计算、轮展开网络或依赖锥特征。

静态参数公式：三stem `3×12,384`，router `275`，suffix `648,000`，四输出head `418,120`，合计 **1,103,547**。原分类模型为1,087,509；差额来自移除关系投影及扩大输出层。实现后仅实例化参数、初始化与fake组件测试，核对合计1,103,547；真实网络前向与梯度尚未实测。

## 3. 数据与标签时序

### 3.1 划分

| 面板 | 独立orbit/明文对 | 四对组数 |
|---|---:|---:|
| TRAIN-small | 262,144 | 65,536 |
| TRAIN-large | 1,048,576 | 262,144 |
| DEV | 65,536 | 16,384 |
| TEST | 262,144 | 65,536 |

small取large固定前缀，只有训练集嵌套；其余集合互斥。

以 `orbit_id=min(P,P XOR α)` 去重、划分和固定方向；此α下代表满足bit6=0。生成1,376,256个互异代表，保留拒绝重复计数。先划分再分组；同一orbit的两个方向不会跨集合。模型的明文对第二端由代表与α重建。

提议公开种子：采样 `20261116`、shuffle `20261117`；init A=31、B=37；null标签置乱train=41/dev=43。种子只规定复现操作，均非密码key种子。各fit使用隔离RNG；small两档lr保持相同初始化和批序，large真实/null保持相同输入批序。

### 3.2 数据量依据与限制

small→large增加4倍独立样本，并固定更新/呈现量，检验覆盖与重复曝光的权衡。没有证据预先保证1,048,576对足够。

TEST 262,144对时，对单个冻结预测器的准确率，最坏方差正态近似95%半宽约0.19pp；两个预测器的配对准确率差保守半宽约0.38pp。这是描述性精度，不是训练样本复杂度或多重检验后的检测保证。四关系共享orbit，统计不能把样本数乘4。

### 3.3 标签和TEST

1. 一次生成全部orbit代表；标签侧保留K于内存。
2. 仅生成TRAIN-large和DEV的4位标签向量，small复用子集；缓存标签供5fit共享。
3. 完成全部训练、DEV选择和checkpoint保存，冻结主候选后，才生成TEST标签。
4. 各模型仅对TEST前向一次，保存最终指标；后续报告只读保存结果。
5. K随后释放。进程中断导致K丢失时本次停止，禁止偷偷另抽K接着跑；保留已完成部分。

总独立对 `1,048,576+65,536+262,144=1,376,256`；每对2块，正式标签共 **2,752,512块加密**。一次加密结果同时产生四标签，不乘4重复加密。

运行前算法正确性门禁另预留最多256次块加密（含KAT与两实现对照按各次调用计数），总密码调用上限 **2,752,768**。门禁属于本次已确认矩阵；实际设备与执行前置条件闭合后，在同一科学周期内执行，历史KAT不抵扣也不恢复许可。开发测试仍使用假oracle。

若TRAIN某关系为常量：该关系保留并标记“TRAIN未见变化”，不根据此结果换掩码；仍按冻结平均损失训练。若四关系全部常量，停止神经拟合，不生成TEST以找新目标。有限TRAIN上的常量不构成全域恒定证明。

| 设置 | 值与解释 |

| fit | TRAIN | lr | init | 用途 |
|---|---|---|---|---|

F5对整行四标签向量做置乱，保持四关系联合频数；TRAIN和DEV用各自独立置乱。F5用置乱DEV选checkpoint，最终在真实TEST上作为预测关联破坏对照；不把其置乱DEV值与真实DEV值作同目标排名。置乱可能保留少量原位或偶然一致，保留相应记录。

每fit呈现33,554,432对；small相当128epochs，large相当32epochs。总5fit最多 **163,840更新、167,772,160对训练呈现、671,088,640个关系标签损失项**。另有10,485,760对周期DEV前向；选中模型的完整TRAIN/DEV/TEST前向共5,308,416对。全部模型前向总计 **183,566,336对**，含训练与评价，无隐含额外诊断前向。

## 5. 基线、指标与判据

### 5.1 TRAIN-only基线

每关系分别估计：

- 常量概率：`q=(ones+1)/(N+2)`，标签按q>0.5取1；平局取0。
- 单明文位树桩：在规范代表的63个变化位中逐位分两格，各格概率同样Laplace平滑；以TRAIN BCE最小选择位，平局选LSB0最小位。无cipher推导特征。

F3/F4对应large基线；F1/F2对应small基线。基线仅用真实TRAIN标签。F5的真实TEST比较使用large真实基线。基线计算属于统计处理，不计神经fit；耗时计总科学预算。

### 5.2 主评价

主模型固定F3。主指标为四关系平均TEST BCE，同时比较上述两种基线。每个orbit先对4关系取平均损失，再计算“基线损失−模型损失”的配对差，样本单位始终为orbit。

采用稳定FP64 logloss。对两个主配对平均差各给97.5%双侧正态近似CI（Bonferroni控制两比较的整体覆盖至少近似95%）；记录标准差、最大绝对损失差以及固定前后半样本的平均差，全部在唯一最终评价时计算。为避免事后判断尾部，预定保守警示：若非有限量，或单orbit的中心化损失差平方占全部中心化平方和超过1%，主统计结论记为不确定；若方差为0则只给面板精确平均差，主近似检验同样记不确定。该警示只是防止明显被极端点支配，通过它也不构成正态近似成立的证明。保持同一分析方法，不因结果改用其他检验。

**概率预测信号门槛（提议）**：两个配对平均差CI下界均>0，且四关系平均相对logloss改善对两基线各≥1%。相对改善=`(L_base−L_model)/L_base`。1%是首轮实用门槛提议，没有密码学最优性证明。

### 5.3 逐关系与辅助结果

每个fit/关系保存rows、ones、BCE、accuracy、balanced accuracy、两类召回、MCC及配对baseline计数。F5的selected TRAIN/DEV对置乱标签评价，TEST对真实标签评价；在字段中标明目标来源，不能把两种目标的差距叫泛化差距。若某类缺失，相关指标写undefined并说明。阈值固定logit>0。

F3的4关系×2基线准确率比较使用两侧精确McNemar，共8项Holm校正，α=0.05；逐关系“准确率信号”需改善≥1pp且校正p<0.05。它是次级结论，与主BCE判据分别报告。F4只作方向一致性描述，不能替换F3。

常量高准确率表示总体偏差；超过基线才支持输入条件信息。随机标签对照、训练差距与两seed用于解释局限。单key试验保持探索性定位；两个seed并不等于两个独立密钥或独立科学复现。

不得把4标签当统计独立，也不称四个sigmoid学会了完整联合输出差分分布。

## 6. 资源、停止与失败解释

建议单GPU，物理设备需运行前明确批准；单卡8小时是总科学周期上限，含门禁、采样、加密、基线、5fit、DEV/最终评价、写盘和关闭。每fit活动上限90分钟（含其评价），余量最多30分钟用于共享数据与收尾；总上限优先，余量耗尽则后续fit不启动。

- GPU目标上限20GiB、主机RSS上限32GiB、单周期产物上限2GiB；数值为建议门槛。
- 静态估计：一个 `[1024,96,64]` FP32特征张量约24MiB；单对卷积及线性前向约4,320万MAC，不含归一化/激活。总显存、吞吐和8小时可完成性尚未实测。
- 实现仅采用现有可验证的预算检查与必要启动保护；协作截止不能称OS硬限。CPU取数/磁盘/原生调用卡住时的终止方式必须在实现验收时明确；没有硬终止能力就如实标注。
- 任一fit非有限loss/梯度、OOM、超时、身份不符或未知退出：停止后续fit，保留部分结果；正式重试0次。
- 截止前无法完成全矩阵与最终评价：标PARTIAL，无TEST就保持未评价；不按部分完成模型临时换主候选。
- 全部预定fit即使DEV无提升也按预算完成，用于区分优化、数据与null；预算内不加宽网络、不换掩码/key、不给额外epochs。
- 旧结果与旧模型原位保留。

- **CLI**：只接一次显式可信模块 `main(argv)`；不增加具体实验名单或按method分支。参考已有外置插件设计。
- **密码**：复用当前SIMON适配器，标签侧独占真实key；模型仅调用自己前向。
- **存储**：沿用data/models/result分工；新method身份拟定 `shared-m-differential-relations-v1`。身份同时记录掩码、位序、key协议、输入适配、checkpoint规则和插件源码，不能冒用旧分类身份。
- 固定key实例通过本次唯一experiment_id与实际数据内容摘要绑定：run.json、数据元数据和checkpoint记录同一experiment_id、真实TRAIN/DEV内容摘要、掩码与编码版本；各fit另记real/null目标版本、置乱种子和实际置乱标签摘要。TEST在冻结后生成，其内容摘要写入原run.json并关联所选checkpoint文件摘要，evaluate同时读取这份记录并严格核对。禁止仅凭相同配置/公开采样种子接受另一次实验的数据。采用现有记录字段，无额外身份文件，无key或key哈希公开。
- 当前source identity与checkpoint API有核心白名单约束；插件自有明确身份和保存加载规则，不向核心增加具体实验白名单。

开发TDD与独立审查重点：toy XOR/popcount双路核标签；bit序；orbit隔离；四对不同标签；loss归一；TEST延迟；null整向量置乱；基线TRAIN-only；严格best读回；budget记账；异常停止；原创新1回归。工程测试采用假oracle与合成输出；任何实际cipher/GPU/优化更新单列授权。验收覆盖Ruff、可用mypy/pytest、干净源码CLI闭环；缺工具或环境如实报告，安装另批准。

## 8. 如何跑：先具备入口，再按单向Git流程执行

### 8.1 当前可执行性

实现更新：通用`--plugin`边界、独立模型和完整实验插件已接入工作树，主控338项指定合成/static测试、Ruff与mypy通过。统一CLI的check/help与fake完整五fit闭环已验证；实际KAT、加密标签、神经前向/优化更新、GPU和Windows运行仍未执行。当前Python最低版本为3.12；历史Windows predictor为3.10且本轮未重新连接验证，须选定兼容的既有解释器。插件以注入方式提供Windows working-set读取和GPU UUID+PCI核对，fake ABI/驱动输出测试通过；实际读数仍须现场验收，缺失即停。GPU显存是1秒节流的合作采样，非连续峰值硬限。临时文件限制在实验根目录；启动脚本仅允许G:\\lxy。总/逐fit/共享wall逐边界检查，最后终态与报告IO仍可能合作迟到，需结合退出码及CLOSING_OK/CLOSING_FAILED；冻结run不伪造覆盖其自身最后写入耗时。以下为已实现语法，check可静态执行，正式run仍以设备/环境/发布许可闭合为前提；没有安装许可。

### 8.2 已实现入口

一个实验配置 `configs/differential-relations-simon6.json` 承载本文件冻结项。源码运行时明确设置PYTHONPATH=src:plugins；插件支持：

```text
cipher-lab check --plugin cipher_lab_plugins.differential_relations.cli --config configs/differential-relations-simon6.json
cipher-lab run --plugin cipher_lab_plugins.differential_relations.cli --config configs/differential-relations-simon6.json --root <实验输出根> --id <新ID> --device cuda:0 --gpu-uuid <批准的完整GPU-UUID> --gpu-pci <批准的4hex域PCI>
cipher-lab evaluate --plugin cipher_lab_plugins.differential_relations.cli --run-record <原run.json> --checkpoint <模型路径> --dataset <已保存数据路径> --output <新评价目录>
```

`check`纯配置校验，不导入科学模块、不生成标签；`run`一次执行本实验固定矩阵；`evaluate`为用户主动重新评价保存数据的独立入口，需核模型/数据身份，不再生标签。上述选项已与通用loader接线。主控已验证check与help以及假oracle/人工输出完整五fit保存—严格加载—TEST—报告闭环。

插件源码目录与核心src通过启动脚本明确加入模块搜索路径；不扫描、不自动发现、不联网加载。CLI与解释器必须来自已验证的同一环境。

### 8.3 发布、启动、取回

1. 用户批准设计后，制定实施计划并完成本地合成验证/独立审查。
2. 取得本次Git发布许可；仅本地提交本实验所需明确文件并push GitHub。现有dirty工作树逐文件核对，保留无关变更。
3. 取得远端同步许可；Windows通过Git fetch并checkout明确提交，dirty则停止。
4. 取得科学运行许可（设备/路径/预算/次数）；执行已同步的一个 `plugins/cipher_lab_plugins/differential_relations/start.ps1`。脚本完成必要路径、覆盖和设备检查，设置环境并调用上述CLI；运行时状态、参数、commit与退出码合并现有日志。
5. 原始记录写 `<root>/data/<id>/`，模型写 `<root>/models/<id>/`，报告写 `<root>/result/<id>/`。一次调用运行固定五fit，不另造runner。
6. 用现有SSH/SCP直接取回这三个指定目录到本地对应的 `data/received-<id>/`、`models/received-<id>/`、`result/<id>/`。实际连接别名与路径在授权时绑定，不额外生成取回脚本。
7. 本地只读保存指标生成图表，复用仅服务result的本地服务，验证响应再给链接。取回过程不触发evaluate、标签再生或模型前向。

SSH仅传启动命令和取结果；科学源码、配置、启动脚本经Git同步。普通SSH断线存活能力需按实际运行方式说明，不保证自动续跑。

## 9. 最小产物与报告

| 位置 | 必要内容 |
|---|---|
| data/<id>/ | 一个run.json（配置/身份/选择/计数/终态/曲线/指标）、一个合并日志、必要orbit与4位标签数据 |
| models/<id>/ | 最多5个best checkpoint，仅模型与任务元数据，无真实key、私有RNG、优化器状态 |
| result/<id>/ | 一个自包含report.html，内嵌方法示意、曲线、各关系基线对照、small/large/seed/null对照与限制 |

科学结果文件保持唯一事实源；HTML只引用run.json保存数值。数据可用紧凑uint64 orbit+标签位包存储，不永久保存展开float张量或完整密文。拒绝制造审批卡、重复SHA清单、receipt、证明目录、预后检脚本或额外取回脚本。

报告开头直接给：执行完成范围；主BCE门槛；各关系超过基线多少；是否观察到数据规模效应；本次单key结论边界。设计阶段仅本文档，没有虚构结果图。
