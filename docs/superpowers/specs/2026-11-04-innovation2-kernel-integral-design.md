# SIMON64 核积分：基线、八轮组合与一次同预算改进

状态：**DESIGN，待用户确认**。2026-11-04。本文件不是执行许可。

用户已选择“SIMON64 核基线 → 八轮组合检查 → 一种同预算改进”，本设计给出具体方法和上限；以下数值与实现选择均为主模型提案，不追溯称用户已经批准。当前只允许调查、设计和审查，不启动加密、训练、solver 或安装。

## 1. 问题与既有证据

研究目标：在 SIMON64/128 的完整选择明文 cube 上，寻找跨独立实验 key 与背景共享的**输出 XOR 平衡组合**。主目标为八轮，六/七轮只作正控。不是原随机明文→绝对单 bit 预测突破，不进行密钥恢复。

现有六轮 cube `{0,4,10}`、七轮 `{0,2}`：bit0 有公开支持集充分证书，后续均通过一把 key、16 背景真实检查。八轮指定高字两位 cube 对 bit0 的 496 个合法 key 反例，不排除其他输出组合。原件保持不动，不用旧已关闭许可。

方法依据：本地 Hwang ePrint2026/340 文本 §4 / Algorithm2，SHA与版本见 `result/20261104-innovation2-kernel-integral-audit/source.json`。本设计是方法迁移，不是论文 SIMON32/15轮或最终版 SKINNY 实验复现；不等待未核清的 SKINNY 变体，不调用旧 I1 证明器。

### 已比较的路线

| 路线 | 收益/风险 | 决定 |
|---|---|---|
| 当前 SIMON64 上建立 parity 核，公开结构引导 cube 对比随机 | 直接填补已有单bit工作缺口；主要风险是评分仍无效、发现的只是继承/平凡关系 | **用户选择的大方向；本设计具体化** |
| 忠实 SKINNY 小cube论文复现再迁移 | 可提供论文锚点，但最终模型/官方代码未核清；容易陷入版本等待 | 本周期不做 |
| 神经 cube 排序 / 二次特征扩维 / 增量消元 | 前者缺有效核基线；扩维可能只复现公开轮剥离；d=64消元未证为瓶颈 | 不做，不作为失败后的备用分支 |

## 2. 科学语义与数学合同

位序固定64位MSB=0，高字X位0..31、低字Y位32..63；实际密码接口保持标准SIMON64/128、合法128位主key调度，无真实中间状态、轮key或额外教师。

固定活跃位集合S（本周期只取输入高字），完整枚举所有2^k赋值。背景清空活跃位，其余位随机。每一行：

```text
P(K,b,S) = XOR_(x in cube(S,b)) encrypt(x,K,r)     # 完整64bit XOR
M[t,:] = bits_MSB(P(K_t,b_t,S))
B_discovery = ker(M) over GF(2)                    # 列基表示
B_screen = B_discovery * ker(M_screen * B_discovery)
B_confirm = B_screen * ker(M_confirm * B_screen)
```

必须保留整个子空间交集，不能只删失败原基；比较子空间/规范RREF，不要求同一组打印基。保存各阶段矩阵或packed行、rank、nullity、基及SHA；保留失败/被淘汰空间，零向量不算发现。

### 八轮不能靠低字继承算推进

SIMON `Y_r=X_(r-1)`。完整64位输出空间保存作诊断，但主指标只用**完全支撑在输出高字X_r的 mask 空间**：

```text
H(B) = image(B) ∩ {u : u[32:64] = 0}
# 若B是64×h列基：W=ker(B[32:64,:]); H的列基=B*W
```

这是交集，不是将完整核基截断/投影到高字，也不是只保留原基本来低字全零的几列。任意原基组合都须容许。另以完整保留矩阵的高字列块 M_H 直接求ker(M_H)交叉核对；在相同累积行上，两种实现的high-only子空间必须相同（嵌入完整mask后比较），否则ERROR停止。

主指标 h_X=dim(H(B))，这里高字是含末轮非线性更新的X_r，不是复制半字Y_r。低字单独或高低字混合关系只作旁证，不算八轮主成功。能解释为已有公共恒等式/低轮关系的高字mask也需单独标注，不能宣称新颖；不将“任意可逆回推到前态”误作排除所有关系的理由。对于固定cube，若某高字输出公开依赖锥缺失至少一个活跃位，则对应单bit积分由无依赖直接解释；将其单位mask张成空间T从H中商掉，主计数为 dim(H)-dim(T)。应验证 T⊆H；若不满足是控制失败，不把负数截零。除无依赖外，仍可能有其他已知/简单结构原因；正维数不自动有新颖性。

有限key数据：`B_true⊆ker(M)`，没有统计下界delta0就不套全key false-accept数值。所有通过结果先标 **EMPIRICAL_SURVIVOR**；旧符号证书只用于其指定bit/cube，不给整个核盖章。独立确认不是理论证明。

## 3. 唯一改进：公开AND相遇评分（非旧ANF分数）

旧八轮支持集评分已饱和，不能原样再跑。本周期只考察一个新的、便宜但未证有效的启发式：活跃位在公开AND门输入的跨支路相遇强度。

用64个输入位的**依赖集合**传播完整八轮公开电路，不取值、不读key。输入依赖为单位集合；XOR/AND结果依赖都保守取并；轮key占位依赖为空。对第t轮（1..8）高字位置i的AND门，父输入依赖为L和R：

```text
a = |S ∩ L|; b = |S ∩ R|; c = |S ∩ L ∩ R|
score(S) = sum_(t=1..8,i=0..31) (9-t) * (a*b-c)
```

`a*b-c` 计入跨支路的不同活跃变量有序配对（同变量被c去掉）。低分假设活跃变量更少/更晚通过AND相遇，可能降低高阶混合；它**不是代数次数、真实依赖、平衡判定或概率界**，也不保证优于随机。依赖集采用同一公开电路上的保守并集，只有明文叶有依赖，固定位仍保留其明文坐标，key/常量不进入集合；不是按采样背景删依赖。评分覆盖全八轮所有32位置AND，不只某个目标bit锥。只在同一k内排名，报告每层分数范围、唯一分数数、截断位置同分数目及两臂重叠；即使评分偏向平凡cube，主指标T商空间也不把平凡关系算收益。与旧支持集饱和不同，不做投影ANF枚举。若候选分数全同，排序无信息；保留随机原序，不按字典序伪造改进。

不在本周期试第二评分、改权重、反向排序、训练网络或加入二次输出特征。评分失败就关闭这个假设。

## 4. 固定候选池与公平比较

本周期仅八轮、输入高字0..31、cube维数k∈{2,3,4,5,6}；不扩大到低字、k>6或九轮。

每k先用固定PRNG生成128个不同的无序k子集，子集内部升序，池按抽取顺序保留。不按旋转同构去重：本设计明示旋转相关性，不把128候选当独立统计样本，也不声称穷尽。

- 随机基线R：池的前8个。
- 结构引导G：按 `(score, 池内原序号)` 取前8个。
- 每k每臂8个，共80个**臂槽位**；重复cube只采集一次，共享原始数据和完整成本说明。每臂按8个cube的名义成本比较，另报真实去重后的执行成本，不能让缓存臂看上去凭空更省。
- 同一k的两个臂具有完全相同的发现/筛选行数与cube点数；评分计算成本单独计入G的搜索开销。候选生成、score和两臂名单必须在正式加密前冻结。

不使用历史SAT witness key/background来挑候选或生成面板。旧高字k2反例不预先屏蔽候选：本轮目标是其他输出组合，而不是再证明bit0。

## 5. 实验序列、采样与选择规则

### 5.1 控制阶段（先通过，才能搜索）

三个固定真实面板：r6/S={0,4,10}、r7/S={0,2}、r8/S={0,2}。每项发现128行、筛选256行、确认2048行；全部为新key/背景，不沿用旧一把key实测。

- r6/r7 必须在全部新行上bit0 parity为0，且证书单位mask e0 **属于**各阶段完整核与high-only交集；不要求这些空间等于span(e0)，旧充分证书不排除其他合法关系。否则停止查协议/实现，不扩候选。
- r8/S={0,2} 的bit0已存在合法反例，但随机面板可能未碰到；不能把“应当出现反例”写成必然通过条件；保存结果，不能因未见反例重抽key。它即使有其他高字mask也允许保存为探索结果，但不改变搜索名单。
- 另两个合成随机函数对照，分别匹配r6与r7 cube大小，每项同样128+256+2048行、每点一个独立64-bit word，组内按公开点身份保持一致；不同面板使用独立随机流。它们不调用真实密码，不是随机排列，不作为对真实SIMON伪mask失败概率的证明。128行后若核非零，视控制警报，停止新增科学调用并调查，不悄悄重抽。

真实/随机对照的全64空间均保存，不能把64输出bit当64个独立积分试验。

### 5.2 八轮发现与筛选

每个被选cube：128个发现(key,背景)行 + 256个全新筛选行，总384行，输出64bit。

使用同一组发现key和同一组筛选key贯穿各cube，便于配对、避免某臂得到不同key；各cube的背景流单独域分离。同一cube出现在两臂时共享行；身份由rounds、完整升序active_bits和phase决定，不含臂名，防止两臂重复时被当成独立数据。key可跨cube重用，但**发现/筛选/确认之间key集合严格不交**；三个控制面板另用control域的key流，不与搜索/确认共享。控制面板内部也按发现/筛选/确认分离key。不同cube共享key意味着不假设cube结果独立。

每臂每k根据筛选阶段的非平凡高字维数排序，选最多1个确认候选：维数降序，完整高字维数降序，再按池原序号；只在非平凡高字维数>0时晋级。每k两臂最多2个，共最多10个臂槽位。名单及完整筛选空间、排序依据先落盘，再请求确认数据。若两臂选同一cube只确认一次。

### 5.3 独立确认

每个晋级cube采集2048个全新key/背景行。计算整个空间交集与高字非平凡维数；不允许从筛选未晋级cube中补位，不允许因确认失败重新选择/重抽。

若都未晋级，跳过确认但仍完成本周期固定比较后关闭；不换评分、不追加k/key/轮数。

### 5.4 随机与身份协议

候选池seed=197101；真实key流seed=197102；背景根seed=197103；随机函数对照根seed=197104。均为公开可复现实验seed，不声称真实实验key对知情者保密。

具体构造：用SHA256对固定周期标签与显式域字段分离出整数seed，再使用Python `random.Random(seed)`；候选池随机抽取去重，key `getrandbits(128)`，背景 `getrandbits(64)&~active_mask`。key流的域只有control/search角色与phase，不含cube或臂名以满足共享协议；候选池域含k，背景域含rounds/cube-id/phase，随机对照域另隔离。key按phase生成独立序列并拒绝流内重复及全周期不同phase/control-search域间碰撞；同一search phase跨cube共享其同一序列不是碰撞重抽。背景在每cube/phase内拒绝重复，记录实际身份/尝试计数。最多每目标采样数×16次抽取，耗尽即ERROR，不无限循环。

实现计划必须冻结精确字符串编码/字节序及测试向量；工程测试用假key和假oracle。真实key值/轮key/内部状态不得落盘/输出；记录key索引、seed方案和流身份，不把key传给评分器/GF2/报告。cube点重复跨不同key是允许的，报告实际加密调用量与不同(key,plaintext)对，而不伪称所有明文全局不同。

## 7. 成功标准、比较和结论边界

- 基线可用：独立合成GF2 oracle、位序与cipher/KAT对照、六/七轮真实正控全部通过；不等于八轮科学成功。
- 八轮组合观察：独立确认后非平凡高字维数>0，报告完整mask、cube、反例数/确认前后空间，标经验发现。只在旧r7低字存在关系不算。
- 对每臂每k报告8个筛选维数、正维数cube数、所选确认cube与最终维数；不把未确认cube称确认成功。
- 改进主要终点：5个k分层中最终确认正维数层数 `C_G` 对 `C_R`。若C_G>C_R且至少一个G胜出是两臂不同cube，则称“本固定候选池上有探索性优势”；若相等，维数差、首次发现成本只作次指标，不改门槛宣称主成功。任何情况不称统计显著、跨seed稳健或新纪录。仅一个候选池，允许的选择机会全部披露。
- null/确认失败如实报告，未证明不存在八轮积分；若只发现已有/平凡关系，不算有价值改进。
- 未核文献覆盖与全key证明不能靠正维数解决；若有好候选，下一周期才考虑独立候选池或正式证明，不在本周期偷偷启动SAT/solver。
