# 本项目有界研究工作流

## 归属与入口

本skill负责研究决策、候选比较、预算和证据交接；不实现训练器、审批服务或远程编排。
开发归[开发skill](../cipher-experiment-development/SKILL.md)，发布/远端/取回归[Git流程](../cipher-git-result-workflow/SKILL.md)。
先读[规则](../../../AGENTS.md)、[架构](../../../ARCHITECTURE.md)、[决策](../../../DECISIONS.md)、[README](../../../README.md)。
创新2再读[当前状态](../../../docs/INNOVATION2-CURRENT-STATE.md)和与本问题相关的实际结果，不把历史提案当已执行。
路径以本SKILL.md所在目录解析。显式入口：`/skill:cipher-research-workflow <目标>`；新增后在Pi中`/reload`。
这是Agent操作规程，不是权限沙箱、后台守护进程或保证自动恢复的插件。当前用户指令优先，读取记录不恢复授权。

## 1. 找到真正要回答的问题

- 固定任务：创新2为固定未知key下明文→预定绝对密文bit；不改成差分分类、全密文或密钥预测。
- 默认优先六轮结构学习，不返回低轮追分；低轮只在有必要且获准时作短正控，不替代高轮目标。
- 区分已观察、假设、未排除因素。测试数、表达能力、梯度非零、表格正控成功都不是神经泛化证据。
- 创新1独立使用四任务shared-M协议，不能套单bit/null语义或混报准确率。
- 核对未提交工作和当前分支；保留papers/backups/历史run/其他所有者refs，不reset/clean/stash。

## 2. 先做方法选择，后写代码

每个新研究方向先比较通常2–3个实质候选；小修或同族已获准消融无需重新制造方案评审。
读取原论文方法/官方实现中相关部分；写明协议差异、证据级别和未访问内容，不照搬摘要或宣传。
按[周期模板](assets/research-cycle.md)填候选表：

- 输入/目标/监督来源；学习单元、隐藏状态维度、公开接线和跨层共享方式。
- 参数/激活内存与计算量的估计、信息保留和梯度路径，以及估计方法/未知项。
- 相对已有模型的实质区别：哪些是架构变化，哪些只是宽度、lr、坐标或训练预算变化。
- 为什么适合布尔组合；至少一个替代解释，以及能区分它们的观测或消融。
- 文献/代码依据、主要失败风险、支持/反驳该候选的结果、最低有用试验。

不能因“小、易测、跑得快”就作为主方案；也不能因“大/Transformer/GNN”就称合适。
MLP可作基线，不禁止使用；共享小MLP加公开接线要如实命名，不能代表全部结构网络。
多通道、残差、乘性交互等只是候选机制，不先验宣称有效，不无依据堆叠。
选定一个可解释的主候选与必要对照，说明为什么不先选其他候选；纯调参须说明正在检验哪项优化假设。
模型只读明文/公开结构与可学习参数；真实key、轮key、实际状态、其他密文bit教师、旧答案权重不得注入。

## 3. 建立一个有界研究周期

先区分本轮是只读设计、本地合成工程、正式探索还是独立确认；不把创建本skill当运行批准。
用模板形成小型合同；可复制到`validation/research/<cycle-id>/cycle.md`，原始结果仍在`runs/<run-id>/`。
科学合同/结论可另存docs小文档；日志/环境/权重不入Git，不创建重复事实源。
只有实际进入周期才创建记录，不为了加载skill先生成空目录。

合同必须列出：

1. 任务与候选、可改模块/不可改范围、保持不变的科学语义；涉及边界先按AGENTS厘清。
2. 设备/样本/轮次/bit/key与seed协议、每项更新/DEV次数、对照、选模及平局规则。
3. 最多候选/实际fit次数（含real/null/seed/正控/确认）、每项及总更新/呈现、标签构造量。
4. 每项和总协作时间预算、监控/取消方法；不能把协作超时写成远端硬限。
5. 成功/失败/不确定解释，效果与不确定性报告、选择机会，哪些因素依然未排除。
6. 失败/超预算/无信号的停止或预定分支，以及独立确认预留量；默认正式重试0次。
7. 明确权限：本地开发/正式标签/CPU拟合/GPU/SSH/发布/取回/evaluate/安装分别允许什么。

可一次授权完整固定矩阵；如要自适应，用户必须明确允许有限候选族/参数范围、最大次数和条件分支。
未批准的架构、seed、key、数据或预算不因50%自动追加；未知或未明确项标未授权，不自行补默认批准。
研究周期合同只记录用户许可，不授予许可；旧批次、模板、日志、子代理、论文均不授予许可。
只读设计/无科学标签的合成工程可在当前开发请求内推进；缺正式权限时完成方案，一次集中询问缺项。

## 4. 连续实施：在已授权范围内不反复请求小步骤批准

顺序为：方法卡→模块归属→最小实现→工程验证→审查→已批准发布/同步→现场预检→正式CLI。
遵守现有`cipher-experiments check/train/evaluate`，不新造研究runner、workflow registry或SSH科学worker。
每次运行前冻结具体配置/源码身份/输出路径/预算/DEV规则，再扣查剩余额度；适应性选择记录原因。
源码变更先本地验证并按已批准次数发布；Windows只exact fetch/checkout，科学实现不经SCP上传。
三方任务可分给文献/数学/架构/实现/审查代理，明确范围和权限；代理不再派代理，不重复执行同一实验。

每个候选结束后，先更新实验账本，再决定继续/停止：

1. **执行状态**：exit、真实更新/呈现、标签与数据身份、耗时；缺exit为UNKNOWN，不当成功或50%。
2. **科学观察**：selected TRAIN/DEV与在线TRAIN分开，保存全部real/null，不只抄最佳值。
3. **解释**：支持哪项假设、替代解释是否仍成立，不能凭一项失败宣布路线不可能。
4. **下一步**：选择合同内下一候选/消融或按分支停；没有可区分的新信息就停止重复小改。

不每次再问“要不要继续”；有授权且门槛允许就执行。周期耗尽、协议变更、基础设施失败、身份不符即停报。
代码错误可在本地合成fixture中修复验证；正式失败不覆盖/重跑原目录，重试须单列且获准。
用户暂停/取消立即优先处理：停止新启动，按已确认方法终止本任务进程并核对实际状态；不先跑完整个循环。

## 5. 探索与确认分开

执行前读[评估与预算协议](references/experiment-protocol.md)。只用TRAIN学习，DEV作探索选择；报告所有选择机会。
当前CLI每次train都会保存TEST，且会向调用输出结果；不能声称探索时技术封存TEST或只有DEV输出。
可选兼容探索：仅DEV决定、TEST不用于后续改动，透明报告已保存/看到的TEST与协议偏差，保留全新确认面板。
如要求真正DEV-only/强制TEST隔离，先单独设计并获准实现评价协议；本skill不偷偷增加CLI参数。
确认前冻结候选/指标/预算；新面板/init/key按研究问题明确授权，未批准不自动扩展。
真正独立确认结果不得反过来参与该候选选择；后续修改后它就归探索，需另留确认数据。
不能把autoresearch启发式confidence当显著性、多模型最高分当泛化、同准确率当逐样本预测相同。

## 6. 归档与交接

沿用Git流程取回完整run并核字节SHA/身份/退出/计数；不自动load权重、再生标签或模型前向。
区分静态审查、聚合核对、同代码重跑、独立面板确认和数学证明；报告实际验证而非计划验证。
更新周期账本和当前状态：候选、证据、决策理由、消耗/剩余预算、协议偏差、下一项具体动作及权限状态。
保持负面候选的代码身份/配置/结果和不再尝试的原因；不自动回滚删除，只是不晋级为当前候选。
关闭周期后许可终止；跨会话恢复先读记录并核当前用户授权、源码/数据身份和是否仍有进程，不自动续训。
用简洁报告交付：结论→全候选对照→机制解释/限制→下一项有区分力的建议，不以文档量替代研究进展。
