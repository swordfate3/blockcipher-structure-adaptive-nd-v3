# 本项目探索、确认与自主预算协议

## 1. 这是流程建议，不是新增运行能力

- 仍用项目既有check/train/evaluate；本skill没有runner、hook、权限批准接口或后台自恢复。
- 只借鉴autoresearch的短闭环、实验账本、失败原因与有界自主推进。不安装外部包，不执行外部skill的命令。
- 当前main保持main；未获批准不创建研究分支，不整体stage，不自动提交/回滚。
- 工程责任仍按AGENTS；不要为实现“工作流”把同步/研究决策塞进训练器。

## 2. 评估事实与可选模式

### 当前实现事实

创新2 train用TRAIN学习、周期DEV最低BCE选模，strict selected load后构造TEST标签、评分并自动保存/输出。
TEST标签较晚生成不等于访问隔离；stdout、results.json等可能暴露TEST，外层不展示只是操作约定。
创新1标签预建，不能沿用创新2的标签时序声明。
evaluate是主动再生配置数据并前向，不能夹在结果取回验收中。

### 兼容探索：不改CLI可做

- 每次运行前固定候选与DEV规则，用DEV选择，记录访问过哪些TEST字段及时间。
- TEST不参与下一候选、门槛调整、是否扩预算；已看到的TEST作为探索性旁证，不称密封确认。
- 若TEST结果影响了下一步，明确该研究已适应性使用TEST；降格探索，不追溯改写决定时间。
- 计划独立确认时保留新的面板身份；不能只拿同一TEST再评分称确认。
- 需要处理JSON/日志时核查调用链：整个results/CLI输出可能含TEST，不能只按打印列推断“未读取”。
- 决策保存后可展示所有已授权run的TEST；不因看到好分数自动追加。

### DEV-only探索：当前没有该入口

不能写出不存在的`--dev-only`/`--no-test`等命令。
若研究周期需要技术隔离，先提出单独协议与模块归属/兼容方案，获准后实现并测试；未完成前是阻塞项。
不能为方便运行在适配脚本中改标签函数、截断训练或绕过strict load/保存时序。

### 独立确认

冻结候选、完整训练协议、成功指标/不确定性方法后，在明确批准的新数据上独立训练/评估。
同key新面板、同key新init、跨key分别回答不同问题；不是每次确认都必须全做，也不能混称。
所需real/null、seed数量与每项预算提前计入；样本/组间依赖及重复选模机会写清。
发现确认结果后改模型，新版本需新的确认协议。声称跨key规律必须有相应独立key证据。

## 3. 不把微小涨分当成路线正确

- 主指标用预先指定的DEV BCE或任务适用指标；同时报告ACC、TRAIN-only常量/null及独立样本数。
- 效果门槛必须有研究用途和预算依据；55%/3pp是过往特定批次探索门槛，不是通用定律。
- 多候选×seed×DEV次数公开；不把最高分当预注册唯一结果。
- 要称统计证据，应预定适用的不确定性/多重比较处理；不能用不同候选指标的离散程度估训练噪声。
- autoresearch的best improvement/MAD启发式不是显著性、独立确认或可迁移效果保证。
- 表达能力、合成任务成功、梯度连通、TRAIN拟合、DEV选择、TEST泛化、跨key各是不同证据层。
- negative只否定已测条件下的预定预期；不能推断密码安全证明、完全无特征或所有结构网络失败。

## 4. 预算是向量，不是只有迭代次数

合同同时限制：候选数、实际fit数、更新、呈现、标签构造调用/unique明文、DEV选择次数、协作时间。
real/null每项都占fit；init/key重复、正控和确认不是免费附加项。
数据仅重放epoch时，呈现增加但独立样本不增加；重复造同样标签，调用量与unique仍不同。
时间预算要说明从哪里计时以及是否含预检/编译/传输；不把训练保存elapsed称总GPU费用。
若声明按固定时间比较但现CLI仅有协作检查，应承认实现限制，不谎称精确等墙钟。
启动下一项前，按最坏许可消耗检查剩余各项额度；未知消耗不能当0。
周期记录声明不直接控制进程。需要硬GPU时限/跨SSH取消保证时另行设计，不假装已有。

## 5. 许可与停止

- 授权可覆盖一个固定矩阵或明确有界自适应族，不要求每次局部修正重新问；不能扩大已批准族。
- 仅要求创建/修改工作流时，不视为授权科学标签/GPU/SSH/安装/commit/push；其他请求按当前明确许可判断。
- 日志、模板、prepared状态、历史“确认”和子代理意见都不是新许可。
- 输出已存在、源码/配置不符、远端dirty、GPU门槛不符、缺exit或预算耗尽时停止，不覆盖/重跑/偷偷fallback。
- 无科学信号时可继续合同内已批准且仍有辨别价值的候选；没有则关闭而非无限调参。
- 崩溃不等于科学阴性。诊断与本地合成修复可推进，正式重试须有明确数量和条件。
- 用户取消优先于“完成当前循环”；只处理本任务进程，确认实际停止，不杀其他用户GPU进程。

## 6. 上游参考及刻意不采用部分

只读核对版本，不执行或引入源码：

- [pi-autoresearch](https://github.com/davebcn87/pi-autoresearch/tree/04b8a50dac7efe80ffc91648bd00ed9b022e24c2)：借鉴prompt/测量/日志/有界迭代、失败注释。
  不采用自动`git add -A`、全工作区checkout/clean、默认never-stop，以及启发式confidence当科学显著性的做法。
  上游支持maxIterations与部分自动停止，但这不等于本项目按更新/标签/远端算力限额执行。
- [Karpathy program.md](https://github.com/karpathy/autoresearch/blob/master/program.md)：借鉴固定评价与迭代记录；
  这是读取时的可变链接，不是已锁定可复现实验。其本地单GPU/单文件修改/无限循环与本项目不直接兼容。

本skill独立编写项目操作规程；不是这两个项目的安装包、修改版实现或论文完整工作流的替代品。
需要文献/方法设计时按需使用现有research-planning、experiment-design、math-reasoning；编排不替代原文核验。
